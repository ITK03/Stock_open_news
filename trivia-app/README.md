# ZATSU — ドパミン分泌型 雑学アプリ（初期実装）

雑学を上スワイプで流し見し、タップで「殴る」ほど演出が派手になるボタンレスアプリ。
Expo SDK 57 / React Native 0.86 / Reanimated 4。

> 広告は**すべてプレースホルダー**（実SDK未導入）。差し替え箇所は後述。

**雑学はサーバー配信のみで、端末に一切保存しない。** 通信が無い間は遊べない
（＝広告を出さずに遊ばれない）。これは意図した仕様で、詳細は「通信必須の作り」を参照。

## 動かす

雑学の配信元が必要。まずリポジトリのルート側で配信ファイルを生成して立てる:

```bash
# リポジトリのルートで
python3 -m src.trivia.build          # data/trivia_source.jsonl → dist/trivia/
cd dist && python3 -m http.server 8080
```

次にアプリ側。**実機からは localhost が使えない**ので、PC の LAN アドレスを渡す:

```bash
cd trivia-app
npm install
EXPO_PUBLIC_TRIVIA_BASE_URL=http://192.168.0.5:8080/trivia npm start
npm run typecheck   # tsc --noEmit
```

実機推奨。**触覚（Haptics）はシミュレータ／エミュレータでは鳴らない**ので、
振動の強弱を確認するには実機が必要。

配信元を渡し忘れると既定の `http://localhost:8080/trivia` を見に行き、
実機では「つながらない」画面のまま止まる（仕様どおりの挙動）。

## 操作

**フィード画面**

| ジェスチャー | 動作 |
| --- | --- |
| タップ | リアクション。**1件につき最大8回**。1〜5回は増幅、6〜8回は MAX 演出を毎回撃つ |
| 長押し（350ms） | **BAD**。オチが砕けて落ち、破壊しきったら次へ送る |
| 上スワイプ | 次の雑学へ |
| 下スワイプ | 前の雑学へ戻る（直近50件まで） |
| 左スワイプ | 詳細画面を開く |

**詳細画面**（右スワイプで閉じる）

タップ／長押しはフィードと同じ。上下スワイプは本文スクロールで、
**スクロール端に達している時だけ**前後の雑学へ移動する。
ブックマークと共有はここにボタンで置く（ボタンレスの例外はこの画面だけ）。

8回目のリアクションで自動的に次へ送る。演出を見せるため約300ms 待ち、
送った直後の約300msは評価系（タップ・長押し）を受け付けない。
**スワイプは止めない**（止めると壊れて見える）。

## 構成

```
App.tsx                       フォント読み込み / GestureHandlerRootView / SafeAreaProvider
src/config.ts                 配信元URL・タイムアウト・先読みしきい値
src/theme.ts                  配色・演出強度・広告頻度の調整つまみ
src/fonts.ts                  同梱フォント（Noto Sans JP の2ウェイト）
src/haptics.ts                振動の5段はしご（撃ちっぱなし、await しない）
src/data/remote.ts            マニフェスト/シャード/詳細の取得（タイムアウト・再試行・検証）
src/hooks/useTriviaFeed.ts    メモリ内キュー・ランダムシャード・先読み・履歴
src/hooks/useDetail.ts        詳細説明の取得（左スワイプ時のみ）
src/hooks/useProgress.ts      AsyncStorage 永続化（タップ回数・BAD・ブックマーク）
src/screens/FeedScreen.tsx    ジェスチャー合成と全体のオーケストレーション
src/screens/DetailScreen.tsx  詳細説明・オーバースクロール・ブックマーク/共有
src/components/
  TriviaCard.tsx              前フリ + オチ（オチは幅いっぱいに自動サイズ）
  ParticleBurst.tsx           ネオンのパーティクル + 衝撃波
  MaxFlash.tsx                5段目以降の全画面演出
  ShatterText.tsx             BAD の破壊演出（無彩色・文字が砕けて落ちる）
  ConnectionGate.tsx          通信が無い間フィードを塞ぐ
  AdBanner.tsx                上下バナー枠
  InterstitialAd.tsx          全面広告枠
```

サーバー側（生成器とデータ契約）はリポジトリのルート:
`src/trivia/build.py`, `data/trivia_source.jsonl`, `SCHEMA.md` の「雑学」節。

### 調整はほぼ `src/theme.ts` だけで済む

- `MODE` — `'dark'` / `'light'` を切り替えると背景と文字色が反転する
- `NEON` — 演出に使う色のプール。**通常時の画面には一切出さない**
- `REACTION_LEVELS` — 演出5段階の粒の数・飛距離・サイズ・時間・衝撃波の大きさ
- `MAX_REACTIONS` — リアクション上限（既定 8）。5段階しかないので6回目以降は MAX を連打
- `ADVANCE_DELAY_MS` / `INPUT_LOCK_MS` — 自動送りの間合いと入力ロック（各300ms）
- `HISTORY_LIMIT` — 下スワイプで戻れる件数（既定 50）
- `INTERSTITIAL_EVERY` — 全面広告を挟む切り替え回数（既定 30）

フォントは `src/fonts.ts`。

## 通信必須の作り

「オフラインで起動して広告を見ずに遊ぶ」を成立させないための作りが3枚ある。

1. **雑学を端末に永続化しない。** `useTriviaFeed` はメモリ内にしか持たない。
   よってアプリを起動し直せば必ず通信が必要になる。AsyncStorage に入れているのは
   タップ回数と保存フラグ（ユーザー側のデータ）だけで、雑学本文は一切入れない。
2. **接続監視でフィードを塞ぐ。** `expo-network` の `useNetworkState()` を見て、
   手持ちの雑学が残っていても通信が切れた瞬間に `ConnectionGate` を出し、
   ジェスチャーを止める。1シャード500件を先読みしている最中に機内モードにされても遊べない。
3. **アプリにフォールバックデータを置かない。** 同梱の雑学 JSON は削除済み。
   配信元に繋がらなければ表示できる雑学がゼロになる。

通信が戻ったら自動で取り直す（ユーザーに再試行を押させない）。

## サーバー負荷をどう軽くしているか

100万件・テキストのみで、**オリジンへの負荷をほぼゼロ**にする構成。

- **クライアントは全件を知らない。** 固定サイズのシャード（既定500件）に分割し、
  ランダムに1つだけ引く。全件を落とす経路が存在しない。
- **マニフェストは件数に依存せず約100バイト。** 100万件でも
  `{version, shard_size, shard_count, total}` だけ。ここだけ短TTL。
- **シャードは不変。** 末尾追記だけなら既存シャードは変わらないので
  `Cache-Control: public, max-age=31536000, immutable` を付けられ、CDN エッジで返る。
  内容が変わった時だけ `version` が上がり、`?v=` 経由で無効化される。
- **1セッションの通信はマニフェスト1回 + シャード数回。** 500件消費して1リクエスト。
- リクエストは数千のシャードに分散するので、特定ファイルへの集中も起きない。

実測（100万件・合成データ）: 生成 5.0秒 / ピークメモリ 79MB / 2000シャード /
1シャード 46KB（gzip 後は実データで20KB前後）。

### ホスティングは未決（要判断）
**GitHub Pages は本番では使えない。** 100万件で150MB級になり、Pages は
1GB/100GB月の枠と「商用利用を想定しない」という前提があるため、広告収益前提の
アプリの配信元には向かない。転送量課金ゼロの Cloudflare R2 か、
S3 + CloudFront を推奨。`src/config.ts` の URL を差し替えるだけで移れるよう、
配信側は**静的ファイルのみ**で完結させてある（サーバーサイドの処理は一切不要）。

## 実装上の判断メモ

**「遅延ゼロ」の作り方** — スワイプ確定時にカードを画面外へ送り出すアニメーションは入れていない。
`drag` を即 0 に戻し、新しいカードの 160ms の入場だけで繋いでいる。
送り出しアニメを足すとその分だけ確実に体感が遅くなる。
代わりに**入場の向き**（次＝下から / 前＝上から）で切り替わりを読み取らせている。

**BAD にネオンを使っていない** — `ShatterText` は本文と同じ無彩色のまま文字を砕く。
報酬の色を BAD に渡すと BAD が快感になり、娯楽として連打される。
衝撃は色ではなく画面の揺れと Haptic で出している（背景が黒なので暗くしても沈まず、
明るくすると報酬の閃光に見えてしまう）。

**BAD はトグルにしてある** — 全ジェスチャーが即実行で誤爆が避けられず、
誤った BAD はコンテンツに恒久的な烙印を残す。もう一度長押しすれば取り消せる
（取り消し時は破壊演出を出さない）。

**詳細ファイルのパスはハッシュで分散** — 100万件を1ディレクトリに置くと破綻するので
FNV-1a で 4096 個に分ける。**アプリ側 `detailBucket` と生成器 `detail_bucket` は
同じ結果を返す必要があり**、UTF-16 で数える（バイト単位にすると非ASCIIのIDだけズレる）。
`tests/test_trivia_build.py` で実際の JS 出力と照合している。

**リアクション回数を ref で持つ理由** — `useProgress` は ref を正としている。
`setState` の反映を待つと「今何回目か」が1タップ遅れ、演出の強度がズレる。

**パーティクルは画面全体レイヤーに絶対配置** — 0x0 の親に置くと Android で親の境界に
クリップされて粒が消える。

**触覚は 4回目以降 `setTimeout` で連打している** — `ImpactFeedbackStyle` は `Heavy` が上限で、
単発では 4回目と5回目の差が作れないため、パルス数で「重さ」を表現している。

**フォントを同梱している理由** — `fontWeight: '900'` は日本語グリフだと Android の
フォールバックに Black ウェイトが無く、iOS ほど太くならない。iOS/Android で見た目を揃えるには
同梱するしかないため、Noto Sans JP（SIL OFL）の Medium と Black を入れている。
**ルートから import してはいけない** — 9ウェイト全部（約48MB）がバンドルされる。必ず
`@expo-google-fonts/noto-sans-jp/900Black` のようにサブパスで読む。
また `fontFamily` を指定した要素に `fontWeight` を併用しない（iOS で合成ボールドが二重にかかる）。

**全画面演出は広告枠に重ねていない** — `MaxFlash` はコンテンツ領域の中だけで完結させ、
上下バナーの上には乗らないようにしている（実広告SDKは自社UIの重ね合わせを規約で禁じているため、
プレースホルダーのうちから同じ制約で作っておく）。`gestureArea` の `overflow: 'hidden'` が
その境界を担保している。

## 広告を実SDKに差し替えるとき

1. `src/components/AdBanner.tsx` の中身を SDK のバナーに置換。
   **`AD_BANNER_HEIGHT` は変えない** — 読み込み前後で本文がずれないようにするための固定値。
2. `src/components/InterstitialAd.tsx` を SDK のインタースティシャルに置換。
   `FeedScreen` 側は `adVisible` の出し入れだけなので、表示/クローズを配線すれば済む。
3. 全面広告の発火は `FeedScreen.advance()` 内の `INTERSTITIAL_EVERY` 判定。
   実SDKはプリロードが必要なので、発火の数枚前から読み込み開始する処理を足すこと。

## 既知の割り切り（要判断）

- **リアクション上限は永続**（意図的）。1件8回で打ち止めになり、記録は端末に残り続ける。
  雑学の件数を大幅に増やしていく前提のため、叩ける総量が実質尽きないという判断。
  **件数が少ないままだとこの前提は崩れる。**
- **ブックマーク一覧は未実装**。ローカルに残るのは id とフラグだけなので、
  一覧を作るなら id から本文を引く経路が別に要る（シャードは id で引けない）。
- **音が無い**。視覚と触覚だけで刺激を作っている。刺激チャネルを1つ捨てている状態で、
  無料の標準機能として入れる方針（SPEC 未確定を参照）。
- **課金・リワード・上限ゲートは未実装**。方針は MONETIZATION.md にある。
- **全面広告のカウントは「前に進んだ回数」**。スワイプと自動送りの両方を数える
  （消費量＝広告露出のため）。セッション単位でアプリ再起動時にリセットされる。
- **アプリサイズが約13MB**。うち約11MB が日本語フォント2ウェイト。
  削るならサブセット化（使用グリフだけ残す）で1ウェイト数百KBまで落とせるが、
  雑学データを後から増やす前提だとサブセットを作り直す運用が必要になる。
- **スプラッシュの黒背景は開発ビルドが必要**。`expo-splash-screen` の設定は
  config plugin なので Expo Go では反映されない（フォント自体は Expo Go でも効く）。
