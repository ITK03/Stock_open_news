# ZATSU 仕様

会話に散らばった決定をここに集約する。**このファイルが仕様の正**。

初期に貼られた Gemini 生成プロンプトは仕様ではない。あの文面には意図と逆の項目が
混ざっていたため（下の「上書きされた項目」参照）、以後は参照しない。

---

## 1. コンセプト

- ターゲット: 短時間で刺激（ドパミン）を求める若年層。
- 通常時は視覚的ノイズをゼロにし、**アクションを起こした時だけ**フルカラーの
  派手なエフェクトと振動で快感を与える。
- UI は極限までシンプル。背景は黒（または白）、文字は反転色のみ。
  **グレーや装飾は一切使わない。** ネオンはアクション中しか画面に出さない。

## 2. 画面

- 最上部と最下部にバナー広告。セーフエリア内に置き、本文と絶対に被らないよう
  パディングを取る。
- 画面中央は雑学テキストのみ。**ボタン類は一切置かない（完全ボタンレス）。**
- オチは極太・特大フォントで画面幅いっぱいに表示する。
  太さは OS 依存にしない（iOS/Android で見た目を揃える）。

## 3. 操作

| ジェスチャー | 動作 |
| --- | --- |
| 上スワイプ | 次の雑学へ。**遅延ゼロ**で即座に切り替える |
| ダブルタップ | リアクション。**1件につき最大5回**。回数ごとにネオンのパーティクルと振動が増幅し、5回目は全画面が弾ける MAX 演出 |
| 長押し | **perfect 評価**（後述）。重めの振動 + 中央に一瞬だけ表示して消える |
| 単純タップ / 下スワイプ | **未割り当て。割り当ては再検討中** |

## 4. データ

**雑学本体はサーバー、ユーザーの行動はローカル。** この線引きは動かさない。

| データ | 置き場所 | 理由 |
| --- | --- | --- |
| 雑学の本文（文字のみ） | **サーバー** | 100万件規模。端末に置かない |
| 各雑学へのタップ回数 | **端末ローカル** | ユーザー個人のデータ |
| perfect 評価のフラグ | **端末ローカル** | 同上 |

- **想定件数は100万件。** 設計はこの規模を前提にする。
- **サーバーの負荷はできるだけ軽くする。**
- **リアクション上限（1件5回）は永久保存。** 件数を大幅に増やすので、
  叩ける総量が実質尽きないという判断。件数が少ないままだとこの前提は崩れる。

## 5. 通信は必須

**オフラインで起動して広告を出さずに雑学だけ遊べてしまう状態を許さない。**
これが通信必須の理由であり、単なる技術的都合ではない。

満たすべき条件:
1. 雑学を端末に永続化しない（保存すると再起動後オフラインで遊べてしまう）。
2. 通信が切れている間は遊べない（手持ちが残っていても止める）。
3. アプリ内にフォールバックの雑学データを持たない。

## 6. 広告

- 上下バナーは常時表示。
- インタースティシャル（全面広告）は**上スワイプ30回ごと**に1回。
- 現段階は実SDK未導入で、視覚的にわかるプレースホルダー。

## 未確定

- **perfect の評価体系。** 長押し = perfect 評価であることは確定。
  未確定なのは「perfect 以外にどんな評価があるか」と「何によって判定が決まるか」。
  現状の実装は単一フラグ（perfect か否か）として扱っている。
- **単純タップと下スワイプの割り当て。** 再検討中のため未割り当てのまま。
- **雑学の配信先ホスティング。** GitHub Pages は容量と商用前提の観点で本番不可。
  Cloudflare R2 等を推奨。配信側は静的ファイルのみで完結させてあるので
  `src/config.ts` の URL 差し替えだけで移れる。
